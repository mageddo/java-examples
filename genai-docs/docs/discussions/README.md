# Discussions

Registro **na íntegra** das reuniões, transcrições e deliberações que originaram o produto. É
a memória bruta do projeto: o que foi dito e decidido, sem síntese.

- Não é fonte da verdade sobre o comportamento atual — isso é papel de
  [`../features`](../features/).
- Não descreve o modelo canônico do domínio — isso é papel de [`../model`](../model/).
- O "porquê" formalizado de cada mudança fica em [`../superpowers/specs`](../superpowers/specs/).

## Objetivo e motivação

Preservar o contexto original — transcrições completas, prints de decisão, documentos de
apoio — apenas convertidos para markdown. Serve de rastro histórico quando surgir a dúvida
*"por que decidimos assim?"*. Divergências entre o que foi discutido e o que foi implementado
são **esperadas**: o código e as `features` prevalecem sobre estes registros.

## Como escrever

1. Copie [`template.md`](template.md) para `AAAA-MM-DD-<assunto>.md`.
2. Preserve o conteúdo como registro histórico; não sintetize nem "corrija" decisões.

## Exemplo

- [`2026-01-10-reuniao-limite-carrinho.md`](2026-01-10-reuniao-limite-carrinho.md) —
  registro fictício de reunião que originou uma decisão de produto.
